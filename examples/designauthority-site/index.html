Triage v0.12.1 foundations

Design intent, written as a contract.

A design authority is a versioned, machine-readable record of an interface system. Coding agents resolve every element against it before they build. Verifiers check the result against the same record. Decisions that would otherwise happen by default get written down, cited, and versioned.

The gap it closes

Interface work is increasingly done by agents. The tools for stating design intent are still prose.

Prose is read, not obeyed

A guide can be precise in a human's hands and lossy in an agent's. Every reader fills gaps with assumptions, and an agent fills them confidently.

Silence still ships

When the record does not say, the build proceeds anyway. The decision happens by default: unrecorded, unreviewed, and impossible to check later.

Feedback is prose too

"This feels off" and "the reverse must show before a one-way action fires, and here it doesn't" cost the same to type. Only one of them can be checked, versioned, and repeated.

What an authority is made of

Plain JSON, a deterministic resolver, and a consumption protocol. No database, no network, the same answer every time.

packs/triage/
  authority.json      identity · version · consumers
  artifacts.json      52 records — components, token sets, patterns
  rules.json          19 enforceable rules (TDS001–015 + interaction)
  golden.json         36 calibration cases — ask, expected, got
  verification.json   claims a verifier can test against a build
  AGENT-PROMPT.md     the consumption protocol for coding agents
{
  "id": "component/px-sw",
  "kind": "component",
  "title": "Switch",
  "summary": "the square switch; track 26×15, thumb 11×11",
  "states": ["default", "hover", "focus",
             "checked", "disabled"],
  "verify": ["[data-sw]",
             "checked toggles aria-checked"]
}

The resolver answers with citations, never with a guess. Ask for "a switch" and it returns component/px-sw. Ask for "rounded corners" and it returns a conflict and refuses.

Nothing is improvised. Nothing is silently skipped.

OutcomeFires whenThe build does
RESOLVED the element matches a recorded artifact build it the recorded way
COMPOSE the element combines recorded parts assemble only in recorded ways
FALLBACK the environment cannot support the primary answer follow the recorded degradation
UNDEFINED the record is silent file a gap; do not invent
CONFLICT the request contradicts a prohibition stop and escalate; do not implement as asked

Two consumers, one record

  1. 1Resolve

    Every element is resolved against the authority before code is written.

  2. 2Build

    The implementation follows the records. Deviations are choices, and choices are recorded.

  3. 3Verify

    A verifier inspects the artifact itself. Agent self-report is evidence, not proof.

  4. 4Report

    Conformance comes back per rule with its evidence. A score is a gate, never proof.

  5. 5Adjudicate

    Conflicts and gaps become precedents and versions, not lost threads.

Each pass through the loop leaves the record stronger than it found it.

How it evolves without rotting

Editorial edits ship as patches

Wording, examples, citations: 0.1.x, no re-freeze.

Semantic changes get a fresh freeze

Pipeline order, thresholds, record formats: 0.2 and up. A build is always checkable against the authority it was built on.

Reversals become precedents

When a decision is overturned, the reversal is recorded with its reason and cited by id. Nothing is quietly overwritten.

Ambitions wait in candidates

An idea enters with the condition that would promote it. Scope grows by evidence, not enthusiasm.

Every conformance claim cites its rule, its implementation, and its evidence. The proposal lives in the Triage repository: spec/proposals/verification-levels.md.

What an authority is not. Not a Figma library, not a lint config, not a moat. It is a contract you version, and it is only as good as its weakest level. Nobody has yet shown that compliant builds behave better in users' hands. That experiment is the next one.
