What is a Design Authority — and what is this page?

What it is

A design authority is a versioned, machine-readable description of an interface system: its components (buttons, fields, menus), its rules (colours, type, spacing, voice), and its fallbacks for what it does not define yet. It is written for two different readers — a coding agent that builds with it, and a verifier that independently checks whether the result actually conforms. It is a contract, not a style guide.

Why it exists

Interfaces drift. Every page, edit and feature makes slightly different choices, until “follow the design” stops meaning anything. An authority makes those choices explicit and testable: builds can be checked against it, and gaps become visible instead of silent.

How this page fits in

1 — Extraction. The deployed language of zhenyoyo.github.io was measured from the rendered site (64 screenshots, computed styles) into packs/phantom 0.2.0 — named Jennu. Every value is tagged base (from the HTML5 UP template) or override (the site's own change).

2 — Consumption. This page is built from that authority. Covered elements are used as defined; where the authority is silent, the result is improvised in character, marked (◌, bottom-right) and filed as a gap record.

3 — Verification. A separate verifier (da_verify, 15 checks) inspects this rendered page — never its own claims — and the results are linked in the footer.

Why it looks like this

An authority is best judged by what it produces, so this audit wears the extracted language it reviews. Where that language has problems, the ledger records them — measured — instead of hiding them.

The worked example — one revision, live

  • v0.1.0 initial freeze — hashed, git-tagged

    Extracted from the template's stylesheet: grey ink canon, the site's pink type misfiled as "deviations". Verified mechanically (its contract re-run clean: 17/17) — but extracted from the wrong layer.

  • rejected owner review of the rendered result

    "The site that exists runs pink type — extract what IS." A version can be internally consistent and still describe the wrong thing; only rendered evidence settles it.

  • v0.2.0 fresh freeze — all pack files re-hashed

    Re-extracted screenshot-first (4 domain teams, 64 captures): canon = the deployed language. The reversal became precedent/pink-ink-canonised — superseded, not deleted. Goldens re-run 21/21; the verification contract rewritten (15 checks), re-run 15/15.

The standing rules

Editorial edit → patch bumpWording, typos, clarifications. No re-freeze needed.
Semantic change → minor bump + fresh freezeNew or changed records, pipeline order, thresholds, tool contracts, taxonomies.
Adjudications become precedentsAccepted / declined decisions persist so agents never relitigate them.
Ambitions become candidatesEvery candidate carries an explicit promote-when bar — no silent canonisation.
Friction is recorded, not smoothedConsumer gaps are filed per workspace; resolutions and proposals are first-class records.
The contract co-versionsGoldens guard resolution; the verification contract travels with the pack and re-runs against every build.

The evolution loop: extract (rendered evidence) → freeze (hashes) → consume (agents resolve & build) → verify (independent checks) → adjudicate (precedent · gap · candidate) → next version. Nothing moves the pack except an adjudicated decision.

How to read this

Every finding below is in one of seven postures. canon the deployed language defines it — the review uses it as is. base a template value the deployment left untouched (still live). override a deployment change — canonised where deliberate, recorded where risky. candidate a promotion dossier with a bar to clear. improvised the system is silent — built in character, marked, filed. gap recorded for the owner; nothing invented silently. defect a plain bug — named, not designed around.

The site under review is a working notebook — unfinished by its own admission — and that is the honest context for every ledger item. Nothing on the reviewed site was modified: the audit is evidence, not a rewrite.
