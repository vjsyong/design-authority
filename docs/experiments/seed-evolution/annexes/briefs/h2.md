# Bookmarks — this session: a tag analytics view

The product exists — source and screenshots in `reference/`. Add a view that
helps the owner understand their tags:

- Navigation to a **tag analytics** view (and a way back).
- It shows, from the bookmarks that exist: how many bookmarks each tag has
  (ordered), and how tag use has accumulated over time (by month).
- These are the first data-visualisation components in the product: charts
  must read as part of the same design language, not a pasted-in widget
  library. The view works with zero bookmarks (empty state) and with many.
- Render it yourself (HTML/CSS/SVG/canvas are all fine); no external chart
  libraries, no CDN.

QA hooks to add (keep all existing): `nav-analytics` (the navigation entry
point), `analytics-view` (the view's root container).

Everything existing keeps working. Where you deliberately change an existing
treatment, say so in your handoff. House process: follow any protocol
documents in `reference/` and the project's records. Finish runnable, with
`HANDOFF.md` and a commit.
