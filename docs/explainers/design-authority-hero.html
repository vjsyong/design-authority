01The contract

A design authority is a versioned, machine-readable description of an interface system: components, rules, fallbacks — written to be read by tools, not just people. A contract, not a style guide.

packs/phantom/ — plain JSON, no database
artifacts.json 29 components · token-sets · layouts
rules.json 8 · prohibitions 2 · fallbacks 4
precedents.json 1 · candidates.json 3
golden.json 21 ask → expected outcome
verification.json 15 conformance checks

03How it evolves

  • v0.1.0rejectedv0.2.0
    frozen, verified — but extracted from the wrong layer. Rendered evidence overruled it; the reversal is recorded as a precedent, not hidden.
  • rule editorial edit → patch bump · semantic change → minor bump + fresh freeze (all files re-hashed).
  • rule precedents persist across versions — agents never relitigate a settled decision.
  • rule ambitions become candidates with an explicit promote-when bar; friction becomes filed gaps.
